## Decisions added before Prompt 5 (these RESOLVE every item in the "Still unresolved" list above; Codex must treat them as decided and must not stop to ask about them)

Also accepted as final: the four "Clarifications supplied for Prompt 4" above (manager ceiling and override semantics, claimant required at creation, liability flag in the transition context, GL success/failure counting as claim activity).

**DD-32 Idempotency-Key (extends DD-21).** Honored on POST only (create claim, submit reserve, add party, upload document, reserve-override). PUT/DELETE are naturally idempotent: the header is ignored and this is documented. Scope of a key: (OrganisationId, UserId, HTTP method, route template). Request hash: SHA-256 of canonical JSON (properties sorted, whitespace removed). Multipart uploads and the dry-run POST /api/claims/validate do not use idempotency. Retention 24 hours (expired records are treated as absent and overwritten; no cleanup job). Concurrency: insert an InProgress row via a unique index (Org, User, Key) in its own short transaction BEFORE running the command; a concurrent request with the same key gets 409 with Retry-After; on completion store the final response (2xx and 4xx); on 5xx or exception delete the record so a retry can run. Same key with a different hash -> 422.

**DD-33 Post-commit enqueue recovery (extends DD-17).** Keep at-least-once delivery. Add a third recurring job GlPostingRecoveryJob (cron */5 * * * *): finds ReserveHistory rows with ApprovalStatus in (AutoApproved, Approved), PostingStatus = Pending, PostingJobId is null, and approval older than 2 minutes, and enqueues PostGLReserveChangeJob with the SAME idempotency key. Safe because the job is idempotent. The manual retry endpoint stays for Failed rows.

**DD-34 SLA job vs interceptor (extends DD-18).** SlaMonitoringJob sets SlaBreachedAt with ExecuteUpdate (bulk update), which bypasses the SaveChanges interceptor, so UpdatedAt is untouched. Its SLA_BREACH_DETECTED audit row is an INSERT into ClaimAuditLog and never modifies the Claim row. The interceptor bumps Claims.UpdatedAt only when a Claim aggregate (or a child through Claim.Touch()) is in a Modified state.

**DD-35 Concurrency and counters.** Concurrent approvals/changes are serialized by the ClaimReserveComponents RowVer: on DbUpdateConcurrencyException reload and re-evaluate the rules once, then return 409. New (Organisation, Year) counter rows: the generator uses UPDATE ... WITH (UPDLOCK, HOLDLOCK), insert-if-missing under HOLDLOCK, and retries up to 3 times on duplicate-key or deadlock.

**DD-36 Balances shown in history.** PreviousBalance/NewBalance are set at approval time, in approval order. History is displayed ordered by ChangeSequence; PendingApproval rows show no balances; balances may therefore not be monotonic by ChangeSequence (documented, not a bug).

**DD-37 Liability determination (D1 section 4.2: UnderInvestigation -> PendingPayment requires "liability determined"). ASSUMPTION.** Add nullable Claims.LiabilityDetermination (string enum: Accepted, PartiallyAccepted, Denied) and nullable LiabilityDeterminedAt. Endpoint PUT /api/claims/{id}/liability {determination, notes?} (handler or above, claim must not be Closed/Withdrawn), audit event LIABILITY_DETERMINED, calls Claim.Touch(). UnderInvestigation -> PendingPayment requires determination Accepted or PartiallyAccepted AND at least one Approved/AutoApproved reserve; otherwise 422 "Liability must be determined (Accepted or PartiallyAccepted) before PendingPayment." The rule applies only to that transition, as in D1 section 4.2.

**DD-38 Notes and coverage endpoints.** Claim notes: PUT /api/claims/{id}/notes {notes}. Coverage: GET /api/policies/{id}/coverage returns the same coverageTypes array that search returns (single source: the Policies row), 404 for an unknown policy.

**DD-39 Tenant identity and standard columns (clarifies DD-24/DD-25).** Domain entities do not carry OrganisationId. Handlers/generators receive it from ITenantProvider/ICurrentUser and pass it as a parameter to domain methods or services that need it (for example the claim-number generator). The interceptor sets the OrganisationId shadow property. Standard audit columns apply to every application table; soft-delete columns (IsDeleted, DeletedAt) apply to business tables that can be removed: Claims, ClaimParties, ClaimRiskObjects, ClaimDocuments, ClaimValidationIssues, LossEvents. NOT applied (documented deviation from D1 section 15.1): ClaimAuditLog and ReserveHistory (immutable, any update/delete of audit rows is blocked; reserve financial fields are immutable per DD-06), ClaimNumberSequences, IdempotencyRecords, and Hangfire-owned tables. Reference tables (Policies, CauseOfLossCodes, ClaimStatusTransitions, Users) get audit columns only.

**DD-40 Assignee list.** The assignee picker and the claims-list handler filter use all users (handler, supervisor, manager), because a supervisor or manager can be the default assignee (creator). GET /api/reference/users?role= remains an exact-role filter; callers omit it to get everyone.
